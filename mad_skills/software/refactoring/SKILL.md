# Refactoring

1. Establish current behavior.
2. Identify the structural problem.
3. Define the smallest useful refactoring boundary.
4. Make incremental changes.
5. Preserve public behavior unless explicitly allowed to change it.
6. Run tests throughout.
7. Remove obsolete code only after verifying it is unused.

Avoid speculative abstractions.
